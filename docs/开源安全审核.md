# 开源安全审核

日期：2026-10-29。范围为本仓库源码、脚本、依赖锁文件、文档、发布快照与 Git 历史；未读取或导出开发者钥匙串凭据，未访问真实集群进行渗透测试。

## 安全与隐私地图

| 项目 | 审查结论 |
| --- | --- |
| 凭据存储 | kubeconfig 正文存本机登录钥匙串；数据库只保存索引与必要元数据 |
| 执行边界 | 用户授权的仓库命令以当前用户权限执行；无应用沙箱隔离 |
| 网络 | 由 Git、Docker、kubectl 和用户命令访问；kubeconfig 可选择 HTTP 或关闭 TLS 验证，导入时警告 |
| 日志 | 已登记的部署凭据跨块脱敏，阶段摘要也先脱敏；未知业务数据仍需人工检查 |
| 文件 | 应用目录 0700、临时 kubeconfig 0600、读取上限及普通文件校验；日志拒绝符号链接分段 |
| 上报与跟踪 | 源码没有分析 SDK、自动日志上传或 ATT 调用 |
| Apple 商店要求 | 本次不申请 App Store；隐私清单与出口申报未作商店提交验收，不宣称可直接上架 |

## 清理内容

- 移除个人机器路径、私人应用标识、内部镜像域名、业务项目名称和真实部署记录。示例改为保留域名与人工数据。
- 应用标识改为公开项目的 `io.github.loveyu233.cicdlocal`；没有复制、迁移或上传任何既有安装的数据与钥匙串。不同标识的版本需要使用者自行规划迁移。
- 流程测试必须显式设置 `LOCALCICD_TEST_SOURCE`，保留 cicddemo 名称、副本来源和 `.test-repos/` 边界检查；不根据开发者机器路径猜测测试仓库。
- 加强忽略规则，排除数据库、日志、凭据文件、本地 CI 配置、测试副本、构建产物和本地工具设置。
- 移除应用图标的附加 EXIF 元数据，并逐个确认压缩像素数据保持一致；不改变图标外观。公开检查会拒绝重新引入的文本／EXIF 元数据。
- 公开仓库从审查后的初始提交开始，私人开发历史只保存在本机，不推送历史分支或标签。公开提交使用维护者的 GitHub 公开身份与 noreply 邮箱。

## 扫描与人工复查

- Gitleaks 8.30.1 扫描原有 81 个提交，未发现匹配规则的凭据；这不代表原历史没有隐私文字，也不能证明不存在未知格式的秘密。扫描器来自官方固定版本，并验证发布包 SHA-256。
- 对全部跟踪文件检查个人路径、敏感文件类型、业务域名、二进制资源和历史提交信息；公开快照只保留源代码、通用文档和生成的应用图标，不附带运行截图或安装包。
- 按文件复查钥匙串读写、kubeconfig 导入、YAML 限制、命令参数与 shell 调用、临时文件权限及清理、日志与阶段摘要脱敏。未发现需阻止源码发布的已确认凭据泄漏；主要残余风险是可信代码执行和用户输出中的未知秘密，见 [安全说明](../SECURITY.md)。
- 使用 OSV 的提交查询核对锁定的 GRDB.swift 7.11.1、Yams 6.2.2、swift-subprocess 1.0.2 和 swift-system 1.8.1，未返回对应漏洞公告。该结果仅反映查询时间与 OSV 数据覆盖，不等于完整依赖审计。
- 可选 GitHub Actions 模板固定 checkout 提交和 Gitleaks 版本／校验和，权限为只读。当前 OAuth 授权缺少 `workflow` 范围，GitHub 拒绝直接上传工作流，因此模板仅保存在文档目录，尚未启用。源码审核与本地扫描已独立执行。
- 仓库已开启 GitHub 私密漏洞报告、凭据扫描、推送保护和依赖漏洞提醒。

## 发布检查

发布前须通过公开快照检查、Gitleaks 公开历史扫描和相关回归。最终测试证据见 [验收记录](验收记录.md)。详细扫描报告与旧历史备份仅留本地；公开报告不复制命中行的潜在隐私内容。

本报告是源码层面的审核记录，不是第三方安全认证，也不承诺“绝对安全”。新增项目命令、认证插件、依赖和权限后需要重新审查。
